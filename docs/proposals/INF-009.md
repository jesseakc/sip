# INF-009: Read-only Redfish discovery and hardware health connector

Status: draft implementation proposal, not implemented
Priority: P1
Area: SIP Infrastructure plugin

## Objective
Add an opt-in, read-only Redfish connector for BMC-backed server discovery, inventory reconciliation and health snapshots, with strict network and credential safeguards.

## Protocol and adapter
- Implement Redfish client over HTTPS with version/capability detection, pagination/links, request timeouts, bounded concurrency, backoff, ETag conditional fetch where supported and vendor-neutral mapping.
- Read only approved GET resources, starting with ServiceRoot, Systems, Chassis, Managers, Processors, Memory, NetworkAdapters/Interfaces, Storage, Power, Thermal and Status/Health. Support vendor variation and missing fields without fabricating values.
- Explicitly forbid POST/PATCH/PUT/DELETE, power actions, firmware updates, reset and remote console operations. Redfish Actions are out of scope.
- Use connector-owned typed observations with source URI, fetched_at, freshness, manufacturer, model, serial, firmware, raw schema version, normalization status and provenance. Never claim a live status from stale data.
## Configuration and network safety
- Opt-in per tenant/installation, operator-managed endpoints, allowlisted hosts/IP ranges and TLS verification by default; no insecure TLS fallback. Credentials through existing secret storage, never database plaintext, logs or API responses.
- SSRF controls: validate DNS and resolved IP on each connection, block link-local, loopback, metadata and private ranges unless an explicit administrator-scoped private-network allowlist is configured. Recheck redirects and Redfish-discovered links; no cross-host link traversal without allowlist.
- Least-privilege read-only BMC accounts, rotation, health check, rate limits, scheduling and connection test. Prevent scanning arbitrary tenant networks; audit endpoint changes and each sync.
- Document network segmentation and deployer responsibility. No automatic discovery scans in v1.
## Mapping and reconciliation
- Map discovered chassis, servers, CPUs, memory and accelerators into canonical SIP assets/components using stable external source IDs. Never silently merge solely on serial; require review for ambiguous matches.
- Dry-run diff before import: create/update candidates, conflicts, missing fields, stale/disappeared components and potential duplicates. Require operator approval before applying inventory changes.
- Persist last successful sync, per-resource errors, raw response references with redaction/retention, and normalized snapshot. Preserve manual edits and lifecycle history.
- Surface health/status observations and firmware inventory in INF-007; allow optional incident suggestion to INF-008 but no automatic outage declaration or customer notification.
## Tests and acceptance
- Contract tests with mocked Redfish payloads from multiple vendors and versions; nested links, partial inventory, paging, auth expiry, rate limiting and schema variations.
- Security tests for SSRF, redirects, DNS rebinding, TLS failures, credential redaction, unauthorized tenant access and forbidden methods.
- Integration flow: configure approved BMC endpoint, preview discovery, reconcile one server and components, view provenance and stale-data banner, handle offline BMC without deleting assets.
- API/docs, installer capability flags, safe defaults, bounded sync jobs and observability metrics.
## Non-goals
- Write/control actions, arbitrary network scanning, IPMI, vendor proprietary extensions beyond optional adapters, continuous high-frequency telemetry (INF-010).

## Dependencies and sequencing
INF-002 for component identity, INF-007 for data center mapping/UI, INF-005 for connector capability gating; can prototype read-only client independently.
