# INF-008: Infrastructure incidents, maintenance and impact workflows

Status: draft implementation proposal, not implemented
Priority: P1
Area: SIP Infrastructure plugin

## Objective
Provide infrastructure-specific incident and maintenance workflows over SIP's shared work orders, assets, notifications and topology, without inventing a parallel CMMS.

## Functional scope
- Define incident record with tenant, incident type, severity, status, affected asset(s), detected_at, acknowledged_at, resolved_at, reporter/source, customer-visible summary, internal notes, and linked work orders.
- Support outage, degraded, maintenance and planned-change scenarios. Track timeline events and acknowledgements with immutable audit history. Incident status transitions are explicit and permission-checked.
- Compute bounded upstream/downstream impacted asset sets from INF-001 relationship graph. Persist impact snapshots with calculation timestamp, graph version and uncertainty; distinguish known impact from inferred potential impact.
- Create or link SIP work orders and maintenance windows; show work-in-progress, planned downtime, change approvals, owner, SLA and restoration verification.
- Integrate with the standalone notifications plugin through events/outbox, not direct email inside this plugin. Human-in-the-loop approval for externally facing messages and AI-generated summaries. Never auto-notify customers from unverified sensor events.
- Dashboard: open incidents, affected services/assets, maintenance calendar, time to acknowledge/resolve and asset downtime with explicit metric definitions.
- Provide safe manual incident creation even when no telemetry connector or AI model is installed.
## Contracts and security
- Reuse core work order and activity models. Define versioned events: incident.created, incident.updated, impact.assessed, maintenance.started, maintenance.ended, incident.resolved. Idempotency keys and outbox delivery; no duplicate notifications on retries.
- APIs for incident CRUD, state transitions, asset impact, work-order links, maintenance windows and event history; pagination, RBAC, RLS, optimistic concurrency.
- Restrict customer-facing fields; redact internal diagnostic logs, sensitive facility details, IP addresses and credentials by default.
- Explicit operator approval for any future infrastructure control command; this PR implements no remote writes.
## Tests and acceptance
- Simulate loss of a PDU feeding two racks, create incident, capture impact, link corrective work order, draft stakeholder notice, record restoration and close with audit trail.
- Verify redundant paths and uncertain impact do not falsely label every dependent asset down.
- Tenant isolation, role access, concurrent state updates, retry/idempotency, missing notification plugin, time zones, backdated maintenance and deleted/archived assets.
- End-to-end API/UI, documentation, fixtures, operational metrics and migration/backfill.
## Non-goals
- Autonomous remediation, BMC control, SNMP writes, automated customer notifications, production telemetry ingestion.

## Dependencies and sequencing
INF-001 for impact graph; INF-006 for plugin surface; INF-005 for runtime isolation. Notification integration should be optional and event-driven.
