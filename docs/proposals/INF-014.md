# INF-014: Infrastructure digital twin and historical state

Status: draft implementation proposal, not implemented
Priority: P1
Area: Shared SIP Core + optional SIP Infrastructure plugin

## Objective
Introduce effective-dated topology and state history to reconstruct infrastructure configurations and incident impact at any past point in time.

## Historical model
- Treat digital twin as a temporal representation, not a 3D rendering requirement.
- Preserve time-bounded asset relationships, slot occupancy, firmware/configuration observations, location changes, maintenance windows and operational states with source/provenance.
- Support valid-time and recorded-time where necessary to distinguish when a fact was true from when SIP learned it. Immutable event history plus versioned snapshots; corrections are append-only.
- Maintain desired, observed, reconciled and historical state explicitly; use INF-015 provenance to explain differences.
## APIs and UI
- Time-travel query: facility/rack/asset topology as-of timestamp, relationship impact as-of incident time, and side-by-side state diff.
- Incident timeline snapshot pinned to graph revision/time so later topology changes do not rewrite historical outage assessments.
- Bound traversal, retention and snapshot storage; PostgreSQL first, no mandatory graph DB or 3D engine.
## Tests
- GPU swap, server relocation, firmware change, power dependency reroute and delayed observation; historical queries return correct occupants/edges before and after changes.
- Tenant isolation, time zones, corrections, archival, retention, migration, deterministic ordering and query performance.
## Dependencies
INF-001 relationships, INF-002 lifecycle, INF-015 provenance, INF-008 incident impact integration.
