# INF-016: Infrastructure capacity, headroom and utilization planning

Status: draft implementation proposal, not implemented
Priority: P2
Area: Shared SIP Core + optional SIP Infrastructure plugin

## Objective
Add capacity planning for rack placement, electrical and cooling headroom, GPU inventory and future growth with explicit data quality and assumptions.

## Scope
- Rack RU allocation and reserved positions, rack weight constraints where provided, installed vs available GPU counts and component slots.
- Electrical nameplate capacity, measured draw, reserved headroom, redundancy groups and PDU/UPS feed topology; cooling design capacity and observed demand where data exists.
- Model units explicitly (W, kW, kVA, A, BTU/h, tons) and conversion assumptions; distinguish measured, rated, allocated and forecast values.
- Planned deployment scenario: propose rack/server/GPU additions, calculate placement feasibility, power/cooling margin and dependency impacts without changing live inventory.
- Dashboard trends and capacity alerts using INF-010 telemetry where configured; manual/design-data-only mode supported with visible uncertainty.
## Correctness and safety
- Never imply accurate power or cooling forecasts without sufficient source data. Display confidence, timestamps and stale/missing inputs.
- Account for redundant power paths and derating; do not sum redundant capacities as independent usable supply.
- Non-destructive simulations, tenant-scoped queries, RBAC, exportable scenario reports, no automatic hardware control.
## Tests
- Rack occupancy conflict, power overcommit, redundant feeds, cooling shortfall, unit conversion, stale telemetry and scenario rollback.
- Synthetic facility dataset, performance, accessibility and API/OpenAPI coverage.
## Dependencies
INF-007 profiles, INF-001 graph, INF-015 quality, optional INF-010 telemetry; schedule after alpha.
