# INF-005: Enforce plugin lifecycle, dependencies and permissions

Status: implementation proposal, not implemented
Priority: P0
Owner: SIP Core / SIPmem platform

## Outcome
Turn manifest discovery into enforceable installation/enablement boundaries so SIP Infrastructure and future vertical plugins are safely optional.

## Expected code surfaces
crates/sip-plugins, crates/sip-api, crates/sip-config, crates/sip-auth, frontend plugin shell, installer integration, tests/

## Implementation specification
### Runtime audit and lifecycle
- Inspect PluginRegistry, manifest validation, plugin-set validation, enabled_by_default, SIP_ENABLED_PLUGINS, backend route mounting and UI hosting; distinguish declared from enforced behavior.
- Implement explicit plugin states discovered/installed/enabled/disabled/incompatible/failed with persisted tenant/installation scope decision. Define whether enablement is instance-wide or tenant-specific; never conflate scopes.
- Resolve dependency graph with missing dependency, version mismatch and cycle errors; fail closed for invalid plugins; no accidental activation from manifest discovery alone.
- Provide validated capability negotiation, compatibility versions and safe migration hooks with transaction/retry/rollback guidance. Plugins must not run arbitrary manifest-provided shell commands.
### Auth and routing
- Enforce permission scopes server-side on plugin APIs, jobs, MCP/AI tools and UI assets; frontend navigation hiding is not authorization.
- Disabled plugin: no actionable API, no registered jobs/tools, no visible navigation, no accessible hosted UI except documented public metadata.
- Prevent plugin from overriding core routes, reading other tenants, accessing arbitrary secrets or escalating privileges; document trusted first-party Rust code vs untrusted third-party bundles.
- Feature/capability discovery endpoint reports *actual* readiness, not manifest promises. Explicitly gate incomplete INF-006 route.
### Installer and testing
- Installer chooses plugins, checks dependencies, reports migration plan and readiness without silently enabling AI models or connectors.
- Test enabled/disabled transitions, stale sessions, permission changes, dependency cycles, startup failures, mixed tenants, route collisions and migration retries.
- Keep existing first-party UI and Migration Studio functional; update docs/OpenAPI.
