# INF-013: Infrastructure identity resolution and source reconciliation

Status: draft implementation proposal, not implemented
Priority: P0
Area: Shared SIP Core + optional SIP Infrastructure plugin

## Objective
Provide shared, tenant-safe asset identity resolution across manual entry, imports, Redfish and future discovery connectors, without silent destructive merges.

## Domain model
- Stable canonical SIP asset UUID plus multiple source identities (source system, endpoint/connector ID, external ID, manufacturer, model, serial, hardware UUID, valid_from/to, confidence and provenance).
- Explicitly separate physical asset identity, component identity, management controller identity, rack slot and observed network address. Never use IP address as immutable identity.
- Record candidate matches, conflict reasons, match evidence, decision actor/time, rejected matches and reversible reconciliation events.
- Enforce tenant-scoped uniqueness where appropriate; same serial may legitimately recur across manufacturers or data sources. Detect and quarantine collisions instead of silently merging.
## Reconciliation workflow
- Idempotent preview/dry run for create, update, link, conflict and retired-source observations; deterministic candidate scoring and configurable thresholds.
- Require operator approval for ambiguous matches, reparenting and changes that overwrite manually curated authoritative fields. Never auto-delete assets when a connector stops reporting them.
- Link imported CSV records and Redfish resources to the same canonical asset when evidence supports the match; preserve service and component history.
- Expose authenticated review queue, decisions, audit timeline, batch operations with limits and undo strategy.
## Safety and tests
- Multi-tenant RLS, RBAC, duplicate event retries, serial reuse, replacement hardware, IP change, BMC replacement, conflicting manufacturer/model, stale sources, bulk imports and concurrency.
- E2E: import a server manually, discover it via Redfish, preview candidate, approve match, verify one canonical asset and full history.
- Shared Core capability, not a data-center-only asset store. Plugin-specific match rules are extensible.
## Dependencies
INF-002 component identity, INF-009 Redfish mapping; coordinate with Migration Studio. Needed before production Redfish reconciliation.
