# INF-003: Secure document ingestion, revision control and applicability

Status: implementation proposal, not implemented
Priority: P0
Owner: SIP Core / SIPmem platform

## Outcome
Complete the shared document pipeline for manuals, drawings, diagnostic files and other asset evidence with immutable revisions and authoritative applicability.

## Expected code surfaces
crates/sip-documents, crates/sip-domain, crates/sip-application, crates/sip-infrastructure, crates/sip-api, migrations/, object storage adapters, tests/

## Implementation specification
### Audit and ingest
- Inspect existing document tables, GET/PATCH/archive handlers, MinIO/S3 adapter, document_chunks and security boundaries; extend rather than rebuild.
- Authenticated multipart or signed upload initiation/completion with tenant-scoped object keys, content hash, size/type allowlist, quotas, streaming, integrity verification and malware-scanning hook/quarantine state.
- Store raw originals immutably in configured object storage, not Postgres. Provide local/self-hosted storage option; fail clearly if unavailable.
- Async extraction jobs with states (queued, processing, ready, failed, quarantined), retry/idempotency, PDF/text support first; preserve page/section anchors, extraction version and provenance. Other formats behind explicit capability flags.
### Version and applicability
- Immutable document revisions with family/document ID, revision number, status draft/current/superseded/withdrawn, effective date, approval actor, reason and predecessor link. Only one current revision per applicability scope unless explicitly modeled.
- Bind documents to asset, asset type, manufacturer, model, firmware range, serial range, site and/or work order using typed applicability rules. Never treat a newer manual as universally applicable.
- Store diagnostic logs with MIME, size, retention and classification; default exclusion from embedding until approved and sanitized.
### Security and APIs
- Authz/RLS on metadata and signed downloads; short-lived access, tenant key separation, no raw object URL leakage. Defend path traversal, oversized files, decompression bombs, malicious PDFs, prompt-injection text.
- Upload, list revisions, approve/supersede, resolve current applicable revision, fetch metadata and authorized download APIs; audit changes.
- Emit reliable indexing events for INF-004 but keep ingestion usable with AI disabled.
### Tests
- End-to-end upload/extract/revision/applicability, tenant isolation, malware quarantine, failed jobs, duplicate hash, concurrent approvals, no-storage failure, backward compatibility.

## Dependencies and sequencing

## Audit-driven amendments (second architecture review)
- Current `crates/sip-documents/src/services.rs` and `processing.rs` contain placeholder structs; the live API uses `sip_application::services::DocumentService`. Inspect and reconcile ownership before adding code. Do not create a third independent document service.
- Current create-document API accepts caller-supplied `storage_path`, checksum and metadata. Replace untrusted path claims with a server-authorized upload session and verified object-store write, while preserving a migration-compatible metadata API.
- Mandatory end-to-end acceptance: authenticated PDF upload -> immutable stored original -> extraction with page references -> revision approval/supersession -> tenant-authorized download -> indexing event -> searchable evidence (once INF-004 is available).
- Include fail-closed storage unavailable/quarantine/oversize handling, malware hook, provenance, applicability and redaction for diagnostics.
