# INF-001: Typed asset relationships and dependency traversal

Status: implementation proposal, not implemented
Priority: P0
Owner: SIP Core / SIPmem platform

## Outcome
Implement a tenant-safe, typed graph of physical asset dependencies and containment without replacing existing parent/location hierarchies.

## Expected code surfaces
crates/sip-domain, crates/sip-assets, crates/sip-application, crates/sip-infrastructure, crates/sip-api, migrations/, tests/

## Implementation specification
### Domain and schema
- Introduce typed AssetRelationship (UUID, tenant/org, source_asset_id, target_asset_id, relationship_type, optional metadata JSON, effective_from/effective_to, created_by, timestamps).
- Initial types: depends_on, powered_by, cooled_by, connected_to, installed_in, feeds, redundant_with. Distinguish directed vs symmetric relations explicitly; preserve the existing parent/child hierarchy as the authoritative containment model unless a compatibility design is approved.
- FK both endpoints to tenant-owned assets; tenant-scoped uniqueness and indexes on source, target, type. Enforce same-tenant edges transactionally and through RLS. No cross-tenant information disclosure in validation errors.
- Define lifecycle behavior for archived/deleted assets and effective-dated edges. Never cascade-delete service history.
### Services and APIs
- CRUD/list relationships with permission checks, pagination, filters, optimistic concurrency and audit activity.
- Traversal API for bounded upstream/downstream impact: direction, allowed types, max_depth, max_nodes, cursor/limits; deterministic ordering and cycle detection.
- Reject self-dependency and cycles for acyclic types (depends_on, powered_by, cooled_by, feeds); allow valid network cycles for connected_to and redundant_with.
- Keep graph querying SQL-native (recursive CTE) initially; no new graph DB.
### Tests and safety
- Integration tests with real Postgres/RLS: cross-tenant denial, mixed type traversal, cycles, archive handling, query bounds, pagination and performance with thousands of nodes.
- Update OpenAPI and docs; migration is additive, reversible where safe; explain backfill of existing hierarchy.
- Ensure graph data remains useful without SIP Infrastructure installed.
