# INF-004: Wire SIPmem evidence pipeline and durable indexing

Status: implementation proposal, not implemented
Priority: P0
Owner: SIP Core / SIPmem platform

## Outcome
Integrate existing SIPmem core/adapters into the live service path, replacing disconnected stubs with permission-safe evidence retrieval and durable indexing.

## Expected code surfaces
crates/sipmem-core, crates/sipmem-adapters, crates/sip-ai, crates/sip-application, crates/sip-api, crates/sip-infrastructure, crates/sip-outbox, migrations/, tests/

## Implementation specification
### Baseline verification
- Audit live POST /api/v1/ai/chat and existing SQL/vector/graph/temporal retrieval, sipmem-adapters pipeline, verification traces, embedding_records and document_chunks; document which are actually wired.
- Wire SIPmemPipeline via dependency injection with production retriever implementations and per-request tenant/user permission context. Never reuse a privileged connection or leak cross-tenant results.
- Retrieval stages: classify/route, retrieve, rank, temporal/applicability filter, cite immutable source IDs + revision/page, verify claim support, synthesize. Explicitly label unsupported answers; never claim verified without evidence.
### Indexing and providers
- Durable outbox/job processing for document and work-order ingestion with idempotent upserts, chunk provenance, embedding model ID/dimension/version, retries, dead-letter, delete/supersede invalidation and reindex CLI/job.
- Model-agnostic BYO provider registry for chat and embeddings with separate mandatory configuration when enabling AI; no silently selected default models. Reject incompatible vector dimensions; support disabled AI and lexical-only fallback.
- Distinguish verified exact SQL facts from model-generated inference. Store trace IDs, citation verification and human feedback without storing secrets.
- Limit retrieval cost/time, prompt size and traversal depth. Guard against prompt injection in untrusted manuals/logs; retrieved content cannot grant tool permissions.
### Tests and benchmarks
- Seed manuals/work orders, ingest/index, retrieve through actual API, verify correct tenant, revision and serial applicability, citation and no-results behavior.
- Verify offline/air-gapped deployment, provider failure, retries, duplicate events, delete/withdraw, tenant revocation, performance, migrations.
- Preserve backwards-compatible API where possible and report changed behavior.

## Dependencies and sequencing
INF-003 event/revision contracts for document indexing; work-order indexing can be built independently. INF-001 graph improves graph retrieval but is not required to start.

## Audit-driven amendments (second architecture review)
- `crates/sipmem-adapters/src/retrievers.rs` currently has SQL/Vector/Graph/Temporal retrievers that all return `Ok(vec![])`; health checks return `Ok(true)`. These are stubs, not healthy production retrievers.
- Wire real implementations and dependency injection into the live authenticated request path; health checks must exercise actual readiness and distinguish disabled, degraded, and operational.
- Mandatory end-to-end fixture: ingest manual and work order, build durable index, ask query via real API, receive cited evidence with source revision/page and correct tenant authorization. Include no-results, superseded document, model outage, and reindex scenarios.
- No default AI models. Installer must require explicit chat/embedding model configuration when those capabilities are enabled; permit AI-disabled and lexical-only modes.
