# INF-007: Data center asset profiles, topology and operational views

Status: draft implementation proposal, not implemented
Priority: P1
Area: SIP Infrastructure plugin

## Objective
Build the first usable data center vertical on SIP Infrastructure: facilities, halls, racks, servers, GPUs, network, power and cooling, with topology and service context.

## Functional scope
- Define versioned, extensible data center asset-type templates for site, building, data hall, row, rack, chassis, server, GPU, accelerator, NIC, switch, PDU, UPS, cooling unit and sensor. Distinguish location, asset, component and part rather than duplicating records.
- Track manufacturer/model/serial, rack unit position and height, power/cooling design limits, warranty, operational state and service ownership. Use optional metadata for non-universal fields, with validated units and explicit unknowns.
- Add rack elevation and topology views with filtering by site, hall, rack, asset type, operational status and work-order state. Render bounded relationship traversal and impacted assets using INF-001. Provide text/table fallback and keyboard-accessible navigation.
- Add GPU and server inventory views with slots and replacement history via INF-002, including installed versus spare components. No invented GPU health data.
- Link manuals, current/superseded revisions and logs from INF-003; evidence-backed diagnostic entry points from INF-004 when configured. AI-off mode must remain fully usable.
- Provide asset onboarding flows: manual creation, bulk template import using existing Migration Studio, validation/dry-run, and export. Preserve external IDs for later Redfish reconciliation.
- Wire authenticated UI under /infrastructure/data-centers and backend routes through the plugin runtime, not an unconditional core route. Disabled plugin must expose no operational UI.
## Data and API contracts
- Reuse canonical SIP tenant/org, locations, assets, asset types, work orders and documents. Only additive, versioned profile configuration and essential placement fields/migrations; avoid a second asset database.
- Define deterministic identity keys for rack positions and components; detect overlapping RU placements, duplicate asset serials only within appropriate manufacturer/model scope, and power-capacity unit mismatch.
- Provide paginated facility/rack inventories, rack elevation, topology neighborhood, placement validation and asset-impact queries. Apply RBAC/RLS to every response.
- Publish stable profile schema and import fixture contract. Profile installation must be idempotent and tenant-scoped; no automatic overwrite of customer customizations.
## Tests and acceptance
- Synthetic facility with at least two halls, multiple racks, servers with GPUs, redundant power and cooling, plus active work orders.
- Rack occupancy constraints and mixed-height placement; impact analysis on PDU outage; GPU replacement retains history; correct current manual selected for model/revision.
- Tests for tenant isolation, RBAC, disabled plugin, profile install/upgrade, missing dependencies, high-density rack view, pagination, import idempotency and AI-off operation.
- Responsive accessible UI, documented API/OpenAPI, migration and upgrade plan, representative screenshots/test fixtures.
## Non-goals
- Real-time telemetry, automated control, DCIM-grade capacity forecasting, live BMC discovery. Those belong to INF-009/010 or later.

## Dependencies and sequencing
Requires INF-006 functional UI/manifest integration; INF-001 relationships and INF-002 lifecycle for full topology/component views. INF-003/004 optional enrichment. Coordinate with INF-005 plugin lifecycle.

## Definition of done
- Verify existing code and other open PRs before implementing; reuse SIP Core instead of duplicating primitives.
- Real implementation with migrations where necessary, API/UI integration, automated tests and updated docs.
- Security review for RLS/RBAC, tenancy, audit and connector safety.
